This architecture reimplements the **Hermes "5-Pillar" framework** as an **Agentic Operating System** on the BEAM, using **Pig** as the persistent nervous system, **Chute** as the cognitive instruction set, and **Ballast** as the secure execution kernel.

### 1. High-Level System Architecture
The system follows a **Hub-and-Spoke** model where a single, long-lived Generalist coordinates specialized domain experts through a shared Virtual Filesystem (VFS).

*   **The Hub (The Generalist):** A persistent `pig/agent` loop acting as the primary social interface. It holds the "Soul" (Identity) and long-term "User Memory" in a dedicated `user.db` SQLite workspace.
*   **The Spokes (Permanent Specialists):** Specialized `pig/agent` actors (e.g., "GleamExpert," "InfraArchitect") with their own domain-specific persistent databases.
*   **The Instrument (Chute/Ballast):** The Generalist does not perform I/O directly; it generates **Chute scripts** to orchestrate specialists and tools. These scripts run in a **Ballast sandbox**, which enforces strict security through static capability verification.
*   **The Bus (VFS Mailbox):** Communication between agents is **Pass-by-Reference**. Agents return a **mailbox path** (e.g., `/inbox/architect/report.json`) rather than raw text, keeping the orchestrator’s context window clean.

### 2. Orchestrator Conversation Structure
The Generalist operates in a **Dual-Mode Loop** within the same Pig process:

*   **Social Chat Mode:** The default state where the Generalist engages in a multi-turn conversation with the user to refine goals and collect context.
*   **Action/Orchestration Mode:** When the Generalist identifies a complex task, it emits a `run_chute(script_name, args)` tool call.
    *   **Suspension:** The Pig runtime **pauses** the Generalist's inference loop.
    *   **Execution:** Ballast executes the Chute script. The Generalist is marked as **"Busy"** and queued while the script performs its work (e.g., spawning subagents, compiling code).
    *   **Resumption:** Once the script completes and writes its final result to the VFS, the Generalist resumes to explain the outcome or request further user input.

### 3. The Orchestrator's Effect Library
To facilitate the Hermes pillars (Skills, Memory, Crons, Learning), the Chute scripts generated by the orchestrator have access to a strictly defined set of **Algebraic Effects** provided by the Ballast host:

**Cognitive & Delegation Effects**
*   **`perform ask_llm(prompt)`**: Triggers a raw inference call for sub-tasks or semantic judgments.
*   **`perform ask_role(role_id, mailbox_path)`**: Sends a structured task to a **Permanent Specialist** and waits for a response mailbox path.
*   **`perform spawn_subagent(manifest)`**: Instantiates a new specialist from a template if one does not exist for the required domain.

**Orchestration & Workflow Effects**
*   **`perform run_tool(name, args)`**: Executes a smaller, specialized Chute script (e.g., `compile_gleam`) that has unique capabilities like `shell_exec`.
*   **`perform schedule_cron(natural_language_time, skill_id)`**: Implements the **Hermes Cron pillar** by adding a message to the BEAM queue to trigger a specific skill at a later time.

**Memory & VFS Effects**
*   **`perform vfs_write(path, data)` / `vfs_read(path)`**: Standard operations for the SQLite-backed workspace.
*   **`perform remember(key, value)`**: Writes to the persistent Key-Value store in the agent's database.
*   **`perform learn(fact)`**: Sends a distilled observation to the **Global Librarian** actor to update the long-term `user.db`.

**Communication Effects**
*   **`perform tell_user(message)`**: Provides mid-process updates or final results to the human interface.
*   **`perform emit_event(payload)`**: Dispatches structured telemetry to the observability system for logging and thought-tracing.
